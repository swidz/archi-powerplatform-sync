# Element names and label language

Version 0.5.0 separates table/view technical identifiers from their localized display names. Version 0.5.1 also uses plug-in type names as element names.

| Object | Archi element name | Display-name properties |
| --- | --- | --- |
| Table | `LogicalName`; `SchemaName` if needed; finally `table.<MetadataId>` | `PowerPlatform-DisplayName` and `PowerPlatform-ObjectName` |
| System view | `<table-logical-name>.view.<savedqueryid>` | `PowerPlatform-DisplayName` and `PowerPlatform-ObjectName` |
| Plug-in | `PowerPlatform-PluginTypeName` (Dataverse `typename`); source name only if the type name is unavailable | Friendly name in `PowerPlatform-DisplayName` and `PowerPlatform-ObjectName` |
| Other components | Published label in the preferred language when supported; otherwise the authored source name | Existing metadata properties; translated record names also have PowerPlatform-DisplayName |

Dataverse savedquery records expose a name, table and GUID, but **no per-view logical/schema name**. The view identifier above is generated by this tool and recorded as PowerPlatform-TechnicalName; it is never falsely recorded as a Dataverse logical name. A supplied logical/schema identifier is preferred if a future source provides one. Technical names do not depend on labels, the signed-in user, or the selected solution. Identity matching still uses environment, kind and source GUID.

## Configuration

In config/settings.js:

```javascript
labelLanguage:"en-US",
```

Language tags are case-insensitive. For example, pl-PL selects LCID 1045; en-US selects 1033. A numeric LCID may be used for additional locale tags. Invalid tags fail before authentication. Existing installed settings are preserved, and the same en-US default applies when this setting is omitted.

## Retrieval and fallback

- Table display names, plural names and descriptions use LocalizedLabels selected by LCID, ahead of UserLocalizedLabel.
- Solution friendly names, model-driven app names, workflow names and view names use the read-only RetrieveLocLabels function. Available solution/app/view descriptions use it too. Only published labels are requested. The solution popup receives localized names before selection.
- Choice, state, status and boolean property labels use the corresponding attribute OptionSet metadata. These requests are limited to allowed properties of the imported platform types, not business table columns.
- Environment, canvas/code app, agent, plug-in and role names are authored strings without a supported per-record translation in these sources. They remain as authored. This setting does not machine-translate content.
- Lookup record names and other formatted annotations may still follow the source user's language. Their .LabelLanguage property says source-user; they are not claimed to be English.

If the preferred label is unavailable, selection falls back to an English (1033) label, then the available label with the lowest LCID, then the source text. The fallback does not depend on array order or the current user's label when localized alternatives are available. PowerPlatform-DisplayNameLanguageCode and PowerPlatform-DisplayNameLanguageStatus record the actual selection; PowerPlatform-LabelLanguage records the requested setting. Missing translated record names generate a preview warning. Failed label reads report partial coverage and read-failed status while retaining available source text.

Label responses and choice definitions are cached during enrichment. Record labels require additional read requests per object and attribute. Disabling includeElementMetadata skips the extended property and choice-label reads, but still retrieves localized object names.

Table field lists in Documentation also use labelLanguage to select attribute DisplayName labels. Technical field names remain the primary identifiers. Field-list reads are controlled separately by includeTableFields and do not retrieve choice values or record data. See [field documentation](metadata-properties.md#table-field-documentation).

## Updating existing elements

Run get-tables, get-views or get-plugins again and review the renamed elements in the common preview. Applying the update changes names and managed properties on the same concepts. Existing GUIDs, manual documentation, custom properties, relationships and diagram occurrences are preserved. PowerPlatform-ObjectName records the display name for tables/views and the friendly name for plug-ins; PowerPlatform-TechnicalName records their element name. The model remains unsaved until the user saves it.
